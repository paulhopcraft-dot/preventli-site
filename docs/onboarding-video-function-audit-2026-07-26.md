# Partner Onboarding Video + Hub vs. Product — Function Audit

**Date:** 2026-07-26
**Scope:** All 5 chapters of the stitched onboarding video, the 14-node workflow map, and all 9 FAQ answers on `https://www.preventli.ai/partner-onboarding`, checked against the live `preventli.ai` production site and the `preventli` product repo at `origin/main` (HEAD `9c2292c`, most relevant fixes `f6b8f3f` and `5bd03bc`, both merged earlier today).
**Trigger:** WorkBetter, a real category-restricted partner, starts using the system tomorrow morning.

---

## Verdict

The hub oversells the product in four specific, avoidable ways. It hides how long the candidate questionnaire actually is — the video's "candidate experience" chapter shows the very first screen and the very last screen and nothing in between, and the one page verified live during this audit (role requirements) opens by default with all 26 free-text boxes visible and ~19 phone-screens of scroll before a single question is answered, not the "guided, plain-English... works on their phone" experience the FAQ describes. It drops the one dataset the JD-driven-questions feature exists to capture — the source PDF's 8-dimension physical-demand rating per task never reaches the candidate, so a candidate can self-clear a task the job description itself rates as high-risk with no indication of that rating anywhere in the flow. It shows a one-click "clinical review" that the code does not gate to any clinician role. And it demonstrates the wrong approval screen entirely for a category-restricted partner like WorkBetter — the video's "Approve & Send" modal is Preventli's own internal admin queue (`/report-review`), not the compact "Reports awaiting your approval" card WorkBetter will actually use inside its own workspace, and the video never shows that WorkBetter's own extra sign-off step exists at all, or that this second approval currently 422s while the report PDF is still failing to generate. None of this is exotic risk-taking by the video's authors — it's normal "record the happy path, skip the boring middle" video-production shorthand — but for a partner whose only walkthrough of the *client-facing* clinical/report side of the product is this video, the gaps are large enough to be a real onboarding hazard, not a cosmetic one.

## Methodology and what could NOT be checked (read this before the table)

- **No transcript, no captions, no Whisper.** The stitched video (`D:\Downloads\preventli-partner-onboarding-full.mp4`, 3:54, 1920×1080) has no subtitle track and no Whisper API key is configured. Every claim below about the video is a claim about **what is visible on screen** — on-screen text, UI state, toast copy, card copy. If the voiceover says something the frames don't show, this audit cannot see it and does not claim to have checked it. Any claim of the form "the video says X" below means on-screen text said X, never narration.
- **Chapters 1-3 are carried forward from live testing done earlier today**, not re-derived here, per instruction. They are included in the table for completeness (so this is one document Paul can hand to WorkBetter's contact) but are marked "(established earlier today)" rather than re-verified.
- **Chapters 4 and 5 are new work in this audit.** Frames were extracted with `watch.py --detail balanced --resolution 1024` over `2:55–3:24` (chapter "05 · Candidate Experience") and `3:20–3:54` (chapter "06 · The Report" — the stitched video's on-screen numbering, which is one ahead of `chapters.ts`'s "chapter 4"/"chapter 5"; see the numbering-mismatch note already flagged in `lib/welcome/chapters.ts`'s comments). The chapter-4 segment turned out to run only from roughly 2:55 to 3:07 before the on-screen card switches to "06 · The Report" — about 12 seconds of unique content, five frames.
- **No authenticated session was used.** Everything about the product is read from `origin/main` source (`git show origin/main:<path>`), not from clicking through a live login. Anywhere this matters (e.g., "does WorkBetter's own login actually show this screen"), it is called out as inferred-from-code, not click-verified.
- **Production environment variables were not checked.** `ASSESSMENT_SCHEDULER_ENABLED` and `ENABLE_NOTIFICATIONS` are both off-by-default in code and gate, respectively, the reminder/escalation sweep and every outbound employer/client email. Whether they are set to `"true"` on the live Render deployment is unknown to this audit — this is flagged explicitly wherever it matters and should not be read as "probably fine."
- **Production data was not queried.** Anything about real assessments, real clients, or real send history is out of scope; "verified live" claims from earlier today are folded in as given, not re-checked.
- **The individual per-chapter `.mp4` files under `public/welcome/` all carry a Jul 26 14:16 mtime**, later than the stitched file used here (Jul 25 22:18). This is most likely a single batch deploy touching all five files' mtimes together, not five independent re-edits — but it cannot be ruled out from a file listing alone that live chapter content has moved since the stitched file was assembled. Treat any chapter-4/5 finding below as checked against the stitched file, with a small residual risk that the individually-hosted chapter file diverges from it.

1. **The role-requirements page's default state is 26 open essay boxes and ~19 phone-screens of scroll before a single answer is given** (4.8, verified live on a real check today). - **Narration was never checked.** No transcript, no captions, no Whisper key. Every video-based claim above is grounded in on-screen text/UI only. If the voiceover adds, contradicts, or clarifies anything the frames don't show, this audit is blind to it.
- **Chapters 1-3 findings are carried forward from live testing done earlier today, not re-verified in this pass.** They are included for completeness of a single reference document, not because this audit re-confirmed them.
- **No authenticated session was used for anything in this audit.** Every product-side claim comes from reading `origin/main` source with `git show`, not from clicking through the live app. Where this matters most (whether WorkBetter's own login truly shows/doesn't show a given screen), it is flagged as inferred-from-code.
- **Production environment variables (`ASSESSMENT_SCHEDULER_ENABLED`, `ENABLE_NOTIFICATIONS`) were not and could not be checked from this repo.** Multiple findings above (reminders actually firing, any employer/client email actually sending) are contingent on these being `"true"` in the live Render deployment. - **The per-chapter hosted `.mp4` files were not separately re-extracted and compared frame-by-frame against the stitched file used here.** All five carry a later mtime than the stitched file (see Methodology).
